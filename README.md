# GoldPin · اپلیکیشن استراتژی PinReady روی طلا (XAUUSD)

[![Build APK](https://github.com/alisport1384/st/actions/workflows/build.yml/badge.svg)](https://github.com/alisport1384/st/actions/workflows/build.yml)

**نسخهٔ ۱٫۴٫۱۱** — چارت TradingView-وار (زوم دو انگشتی + تمام‌صفحه)، لاگر کامل (`md` + `txt`)،
هشدار «سفارش مسلح شد» و مستندات کامل ساخت از صفر تا صد در پوشهٔ [`docs/`](docs/00_OVERVIEW_FA.md).

اپ اندروید برای **چارت‌کشی، بک‌تست و تست زندهٔ کاغذی** استراتژی PinReady روی طلا.
همهٔ محاسبات داخل خود گوشی انجام می‌شود؛ هیچ سرور واسطی وجود ندارد و هیچ کلید API لازم نیست.

> **فایل نصبی آماده:** `GoldPin-1.4.11-24.<sha>.apk` (نسخهٔ ۱٫۴٫۱۱ — امضاشده، قابل نصب روی اندروید ۷ به بالا)
> مسیر ساخت داخل همین مخزن: `app/build/outputs/apk/release/app-release.apk`

> **۱٫۳٫۵ — رفع فریز حالت لایو (تأییدشده روی دستگاه):** ریشهٔ فریز یک رشتهٔ خطای
> صدهاهزارنویسه‌ای بود که از `JSONException` تا یک `TextView` در هدر می‌رفت و نخ رابط را
> در صفحه‌آرایی متن قفل می‌کرد. همراه با آن، باگ پارسر Yahoo (`indicators` یک
> `JSONObject` است نه `JSONArray`) رفع شد — یعنی حالت لایو از این نسخه **واقعاً داده
> می‌گیرد**. ابزار تشخیص `AnrWatchdog` هم اضافه شده که در هر فریز، پشتهٔ نخ اصلی را
> در لاگ ثبت می‌کند. جزئیات در
> [`docs/13_CHANGELOG_FA.md`](docs/13_CHANGELOG_FA.md) و
> [`docs/14_TROUBLESHOOTING_FA.md`](docs/14_TROUBLESHOOTING_FA.md).

> **۱٫۳٫۱ — رفع باگ:** باد شدن حجم کندل باز در حالت لایو (که نتیجهٔ لایو را از بک‌تست
> جدا می‌کرد) ، کشته‌شدن باکس‌های ناحیه به‌دست سقف نمایش (روی دادهٔ نمونه: **۰** باکس فعال
> در برابر **۲۴** باکس فعال بعد از رفع) ، برچسب «منقضی» در تب سفارش‌ها ، مجوز لرزش ،
> فریز نخ رابط هنگام بازیابی وضعیت و به‌روزرسانی زنده ، و چند مورد دیگر.
> فهرست کامل در [`docs/13_CHANGELOG_FA.md`](docs/13_CHANGELOG_FA.md).

## استراتژی پیاده‌شده

زنجیرهٔ کامل، دقیقاً همان چیزی که در اسکریپت Pine نسخهٔ ۶ پیاده شد:

```
کندل مهم → Ready (BU/BE) → pinBU/pinBE → روند (HH/HL/LL/LH)
        → ناحیهٔ فیکس‌رنج (الگوریتم نسخهٔ ۲ کارفرما، ۲۴ ردیف)
        → تایید میانی → ناحیهٔ ولوم کم (تریگر ۱) → ناحیهٔ ولوم زیاد (تریگر ۲ / چارت)
        → ورود (لیمیت روی لبهٔ ناحیه) → حدضرر → TP1 ۳۸٪ → TP2 ۵۰٪ → حدسود ۱٫۲۷۲ → سر‌به‌سر
```

* الگوریتم ناحیه‌ها **نسخهٔ ۲** است: POC هیچ نقشی در ساخت ناحیه ندارد. برای کندل صعودی، ردیف‌ها از کف
  به سقف خوانده می‌شوند؛ ردیفی که رشد در آن متوقف می‌شود «قلهٔ اول» است (کف ناحیه = مرز بین قله و ردیف
  کوچک‌ترِ قبلش) و ردیفی که افت در آن متوقف می‌شود «درهٔ اول» است (سقف ناحیه = مرز بین دره و ردیف
  بزرگ‌ترِ بعدش). برای کندل نزولی کاملاً قرینه.
* ناحیه‌ای که کلوز داخل/روی آن باشد **فیکس‌رنج معتبر نیست** و به‌صورت خط‌چین خاکستری («ردشده») نمایش داده می‌شود.
* باکس ناحیه وقتی پاک می‌شود که یک کندل **تریگر ۲** از سمت دور آن بسته شود.
* باکس ولوم کم **یک‌بارمصرف** است: یک ورود و یک خروج، معامله بشود یا نشود.
* «ولوم زیاد» = بیشتر از کندل قبلی ، «ولوم کم» = کمتر از کندل قبلی (پس از بسته شدن کندل سنجیده می‌شود).
* موتور فقط با **کلوز** تصمیم می‌گیرد → هیچ ریپینتی وجود ندارد. کارگزار کاغذی اما سفارش لیمیت را
  با قیمت زنده پر می‌کند، مثل یک کارگزار واقعی.

آزمون‌ها دقیقاً همان مثال عددی شما را بازتولید می‌کنند:
`engine/src/test/kotlin/.../ZoneTest.kt` → ناحیه ۱: مرز ۱۲۵|۳۲۵ تا مرز ۱۱۷|۲۲۶ ، ناحیه ۲: مرز ۴۷۲|۴۸۹ تا مرز ۲۱۷|۳۹۰.

## گرفتن فایل نصبی از GitHub Actions (بدون سیستم محلی)

فایل نصبی به‌صورت خودکار در Actions ساخته می‌شود —
[`.github/workflows/build.yml`](.github/workflows/build.yml):

1. تب **Actions** ← آخرین اجرای «Build APK» (یا *Run workflow* ← *Run*).
2. پایین صفحه ← **Artifacts** ← `GoldPin-1.4.11-apk` را دانلود کن.
3. از zip بیرون بیاور → `GoldPin-1.4.11-24.<sha>.apk` نصب‌شدنی است (امضاشده ، همراه `sha256`).

برای انتشار ماندگار: `git tag v1.4.11 && git push origin v1.4.11` → فایل در **Releases** قرار می‌گیرد.
هر اجرای CI امضای APK را با `apksigner` تأیید می‌کند و آزمون‌ها را هم اجرا می‌کند
(آزمون‌ها در job جدا هستند تا خرابی‌شان مانع گرفتن فایل نصبی نشود).

## ساخت (Build)

```bash
# پیش‌نیاز: JDK 17 و Android SDK (platform 34 + build-tools 34)
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/android-sdk

./gradlew :app:assembleRelease      # ساخت APK  → app/build/outputs/apk/release/
./gradlew :engine:test :app:testReleaseUnitTest   # آزمون‌ها
./gradlew :cli:installDist && ./cli/build/install/cli/bin/cli \
    --csv data/xauusd_m1.csv --vol real      # بک‌تست خط فرمان روی فایل CSV
```

APK با کلید `keystore/goldpin.jks` امضا می‌شود (رمزها در `app/build.gradle.kts` — برای پروژهٔ شخصی).
اگر می‌خواهید کلید خودتان باشد، فایل را عوض کنید و رمزها را در `signingConfigs` بگذارید.

اگر روی سیستم‌تان Gradle نصب نیست، یک بار `gradle wrapper --gradle-version 8.7` بزنید تا `./gradlew` ساخته شود.

### ساختار پروژه

```
engine/   موتور استراتژی، Kotlin خالص و بدون اندروید (قابل تست روی JVM)
          core/Types.kt · VolumeProfile.kt (الگوریتم v2) · Engine.kt (چهار موتور) ·
          PaperBroker.kt (سفارش/خروج پله‌ای/سر‌به‌سر) · Reports.kt · Json.kt · Store.kt
cli/      هارنس خط فرمان برای بک‌تست روی CSV (بدون گوشی)
app/      اپ اندروید — ChartView (چارت و ژست‌ها) · EquityChartView · Feed · Storage ·
          EngineService (لایو) · MainActivity (پنج تب)
```
